# Домашнє завдання: бібліотека

Тема нова, а принципи ті самі, що на лекції. Ви змоделюєте невелику бібліотеку: книги, журнали й аудіокниги, читачів і саму бібліотеку.

## Що потрібно зробити

### 1. Клас і об'єкт та абстракція

- Створіть абстрактний клас `Item(ABC)` з атрибутами `title` і `year`.
- Додайте абстрактний метод `loan_days()` (на скільки днів видається) і звичайний метод `describe()`, який використовує `loan_days()`.
- Додайте атрибут класу `library_name`, спільний для всіх примірників. Тут він потрібен, щоб показати різницю між атрибутом класу та атрибутом об'єкта: змініть `Item.library_name` і переконайтеся, що нова назва з'явилась у всіх примірниках.

### 2. Наслідування та поліморфізм

- Створіть `Book`, `Magazine`, `AudioBook`. Книга видається на 21 день, журнал на 7, аудіокнига на 14.
- `Book` має додатковий атрибут `author`, а `describe()` у нього перевизначено через `super()`.
- Покажіть поліморфізм: пройдіть циклом по списку з усіх трьох видів і виведіть `describe()`.

### 3. Інкапсуляція

Створіть клас `Reader(name, pin)`:

- захищений список `_borrowed`, який зовні можна лише прочитати (властивість `borrowed` повертає кортеж);
- ліміт: не більше 3 примірників одночасно (книг, журналів і аудіокниг разом), інакше `ValueError`;
- штраф `fine` як властивість із сеттером: від'ємне значення заборонено (`ValueError`), на початку штраф дорівнює 0;
- метод `pay_fine(amount, pin)`, де PIN зберігається в полі `__pin`, як у `BankAccount` з лекції. Невірний PIN дає `PermissionError`, а сума, більша за штраф, дає `ValueError`.

### 4. Композиція та MRO

- Клас `Library` містить усередині список `Item` і список `Reader`. Методи: `add_item()`, `register()`, `lend(reader, item)`, `give_back(reader, item)`.
- `lend()` має кидати `ValueError`, якщо примірник уже виданий або ліміт читача вичерпано. Як саме бібліотека пам'ятає, що примірник виданий (прапорець на `Item` чи словник у `Library`), вирішуйте самі.
- Додайте клас-домішку `Downloadable` з атрибутом `size_mb` і методом `download()`. Зробіть `AudioBook(Downloadable, Item)` і виведіть `AudioBook.__mro__`.

  Підказка: якщо `Downloadable` має власний `__init__`, він мусить передати решту аргументів далі за MRO, інакше `Item.__init__` не викличеться:

  ```python
  class Downloadable:
      def __init__(self, size_mb, **kwargs):
          super().__init__(**kwargs)
          self.size_mb = size_mb


  AudioBook(size_mb=120, title="Кобзар", year=2020)
  ```

### 5. Власний клас на зразок `timedelta`

Створіть клас `Duration`, який описує проміжок часу з точністю до мілісекунд:

- Конструктор `Duration(days=0, hours=0, minutes=0, seconds=0, milliseconds=0)`. Усередині все зберігається в одному захищеному полі `_total_ms` (кількість мілісекунд).
- Доступ до цього поля йде через властивість `total_milliseconds` із **геттером і сеттером**. Сеттер забороняє від'ємні значення (`ValueError`), а конструктор рахує загальну кількість мілісекунд і присвоює її через `self.total_milliseconds = ...`, щоб перевірка спрацьовувала й при створенні. Приклад сеттера дивіться нижче.
- Властивості лише для читання (без сеттера): `days`, `hours`, `minutes`, `seconds`, `milliseconds`. Кожна повертає **залишок** після повних більших одиниць. Наприклад, `Duration(hours=26, minutes=70)` має дати `days == 1`, `hours == 3`, `minutes == 10`, `seconds == 0`, `milliseconds == 0`.
- Метод `total_hours()`, який повертає весь проміжок у годинах (може бути дробовим).
- Методи `add(other)` і `subtract(other)`. Вони **не змінюють** поточний об'єкт, а повертають новий `Duration`. Якщо результат віднімання від'ємний, викличте `ValueError`.
- Метод `is_longer_than(other)`, який повертає `True` або `False`.
- Використайте клас у бібліотеці: додайте в `Item` метод `loan_period()`, що повертає `Duration` на основі `loan_days()`. Потім додайте в `Library` метод `overdue(item, kept_for)`, який приймає `Duration` (скільки читач тримає примірник) і повертає `Duration` прострочення. Якщо прострочення немає, поверніть `Duration()` з нулем. Зверніть увагу: `subtract()` кидає `ValueError` для від'ємного результату, тому спершу перевірте `is_longer_than()`.

#### Приклад: як працює сеттер

Сеттер дозволяє виконувати код щоразу, коли атрибуту присвоюють значення. Зазвичай там перевіряють, чи значення допустиме:

```python
class Thermostat:
    def __init__(self, target):
        self.target = target

    @property
    def target(self):
        return self._target

    @target.setter
    def target(self, value):
        if not 5 <= value <= 35:
            raise ValueError("Температура має бути від 5 до 35")
        self._target = value


t = Thermostat(22)
t.target = 25
print(t.target)
t.target = 100
```

Як це читати:

- Реальні дані лежать у захищеному полі `_target`, а `target` — це «фасад» для доступу до нього.
- Дві функції мають **однакову назву**. Перша з `@property` — геттер (читання), друга з `@target.setter` — сеттер (запис).
- Ззовні все виглядає як звичайний атрибут: `t.target = 25` і `print(t.target)`, без викликів на кшталт `set_target()`.
- У `__init__` ми пишемо `self.target = target`, а не `self._target = target`. Тоді початкове значення теж проходить перевірку.
- Останній рядок прикладу викличе `ValueError`, бо 100 виходить за допустимий діапазон.
- Якщо сеттера немає, спроба присвоїти значення дасть `AttributeError`. Так ви й зробите для `days`, `hours` та інших властивостей лише для читання.
